# 风格库策略

## 结论

当前 Gallery 的 13 个条目是“真实九格处理证据”，不是 13 个已经完成同等质量控制的视觉风格。主要问题不是数量，而是比较条件和风格轴不一致：多个条目都落在 3D、毛绒、玩具或写实大类，且每张代表图来自不同角色、不同表情和不同提示词。

因此，当前选择器可以证明某条路线跑通过，但不能用来回答“哪个风格更适合这个角色”，也不能把 13 张图当作严格的风格竞品对照。

## 竞品带来的真正启发

[da-motion-sticker-skill](https://github.com/avocadotear/da-motion-sticker-skill) 的 36 个预设并不只是把“3D 漫画”换 36 个名字。它把差异分布在六条可观察的视觉轴上：

| 视觉轴 | 代表差异 |
|---|---|
| 材质与形体 | 软陶、短绒毛、搪胶、定格黏土、毛毡、纸雕 |
| 线稿与印刷 | 手绘涂鸦、蜡笔、报纸漫画、网点、黑白漫画、Riso、丝网印刷 |
| 文化媒介 | 浮世绘、年画、国潮剪纸、水墨 |
| 数字时代 | 像素、街机、Y2K、VHS、Windows 95、Mac OS 图标 |
| 表情语法 | 日漫夸张、美式 Meme、Reaction GIF 截帧、Emoji 拟人 |
| 身份构图 | 真人头+卡通小身体、半写实 3D 大头、Emoji 3D 混合 |

它还有一个容易被忽略的产品优势：36 张静图和动图使用同一个角色锚点。用户看到的是“同一个角色换风格”，而不是“13 个角色各自换了一种渲染器”。

## 当前 13 个条目的审计

| 当前条目 | 重叠或缺陷 | 处理建议 |
|---|---|---|
| `3d`、`cute`/`soft-plush`、`fantasy-plush` | 都容易读成毛绒/玩具 3D；`3d` 当前证据图本身就是毛绒玩具 | 保留一个通用 3D 玩偶档；`soft-plush` 只保留短绒毛和柔软触感；Fantasy 需要明确魔法材质/服装证据 |
| `realistic`、`fashion-realistic` | 人物和姿势差异大于渲染差异 | 合并为写实基线；时尚写实作为有明确美妆、布料和棚拍光的子风格 |
| `chibi`、`kawaii-anime` | 都是大头、圆眼、柔和高光 | 拆成“比例轴”（big-head chibi）与“线稿/眼睛轴”（kawaii anime），必须在提示词和证据图中同时体现 |
| `manga` | 当前鱼形案例更像装饰性国潮插画，黑白、网点、速度线等漫画证据不足 | 改成 `anime-reaction` 或 `black-white-manga`，以表情语法而非题材命名 |
| `clay-cute` | 当前案例的黏土指纹、雕塑体积和定格痕迹不够明显 | 与 `soft-clay`/`clay-stop-motion` 二选一，补材质验收项 |
| `hand-drawn`、`pixel-art`、`mascot-toy`、`caricature-3d` | 视觉锚点相对清楚 | 保留，但补充每个风格必须出现的 2–3 个可观察 cue |

## v0.4 目标候选（未验证，不进入选择器）

目标仍是 12–16 个，而不是直接复制 36 个。建议用下面 16 个高区分度家族替换当前重叠项：

1. `plush-doll-3d`：短绒毛、填充体积、收藏玩偶比例。
2. `realistic-photo`：皮肤、布料、摄影光，不使用 Q 版比例。
3. `soft-plush`：柔软短绒毛和温和暖色，区别于塑料和黏土。
4. `soft-clay`：软陶体积、手指纹理、哑光反射。
5. `vinyl-toy`：光滑搪胶、盲盒比例、色块设计。
6. `big-head-chibi`：头部占比 50%–65%，极短四肢。
7. `anime-reaction`：爆筋、泪瀑、集中线等表情语法。
8. `hand-doodle`：歪线、便签速写、故意不精致。
9. `black-white-manga`：高反差墨块、少量灰阶、沉默崩溃。
10. `pixel-art`：8/16-bit 限色和游戏技能姿势。
11. `retro-halftone`：Ben-Day 网点、CMYK 套色偏移。
12. `ink-wash-meme`：水墨干湿变化和大面积留白。
13. `paper-cut`：扁平剪纸负形和纸张边缘。
14. `y2k-web-meme`：低清 PNG、镭射、星光和网络语感。
15. `windows-95-ui`：错误框、进度条、桌面助手语法，元素必须局部化。
16. `emoji-hybrid`：角色身份与 3D Emoji 身体语法结合。

这些是产品候选，不是已完成的证据。没有同一锚点的九格静图、真实动作 GIF/WebP、route、processing 报告和 manifest lineage，就不能把候选标为 `verified`。

## 验证门槛

每个新风格必须使用同一张经过确认的角色锚点和同一组九个反应，只改变风格提示词。最低交付为：

- 240×240 静图和真实动作 GIF/WebP；
- 检测到的 3×3 layout；
- 来源 route 与 processing 报告；
- 至少两个风格专属 cue 的人工检查，例如“网点+套色偏移”或“短绒毛+填充体积”；
- `artifact-manifest.json` 中可追溯到批准静图、提示词、视频和交付物的 SHA-256 链路。

选择器只读取通过上述门槛的条目。未验证候选可以作为 pending preset 被用户显式编译用于受控试验，但不能出现在“真实验证风格”表里，也不能为了凑 36 个而降低门槛。

## 迁移规则

- 保留 `cute` 作为兼容 ID，推荐用户使用 `soft-plush`。
- 旧 Gallery 证据继续可审计，但标注为 legacy case，不把不同角色的图拼成风格排名。
- 新 Gallery 先完成同一角色的受控对照，再逐个加入 `gallery/index.json`；不批量复制竞品的 36 个名字。
- 只有完成媒体重生成和验证后，才更新 README 的“真实验证风格”数量。
