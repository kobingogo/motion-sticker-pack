# 一套动态表情包，为什么不能用一个文件打天下？

## 从角色图到微信、小红书、抖音、WhatsApp、Telegram 的实战教程

第一次做动态表情包时，很容易把“能播放”当成“能导入”。九宫格视频在播放器里正常播放，只能说明它适合展示；聊天软件真正需要的，可能是一张 GIF、一张透明 WebP，或者一个没有声音、时长更短的 VP9 WebM。

这不是同一个文件换个后缀就能解决的问题。展示视频和聊天贴纸处在两个分发层。

本文以 `motion-sticker-pack` 的真实工作流为例，说明怎样从一张角色图开始制作表情包，再把结果分别用于微信、小红书、抖音、X、WhatsApp 和 Telegram。版本边界按 2026-08-27 可访问的项目文件与平台公开说明整理；客户端入口和限制可能随版本变化。

## 先记住这个判断

同一套表情包，至少要准备两类交付物：

| 用途 | 推荐文件 | 适合做什么 |
|---|---|---|
| 内容展示 | 普通 MP4 | 发 X、小红书、抖音，展示整组案例和制作过程 |
| 聊天使用 | 单张 GIF / WebP / PNG / 平台专用 WebM | 导入聊天软件的自定义表情或 Sticker Pack |

项目当前的 X 宣传片是 1080×1350、H.264、无声 MP4。它的透明通道已经拍扁到深色背景里，所以适合发帖，不适合作为透明聊天贴纸的源文件。聊天路线应使用切出来的单张文件，必要时再按平台规格转换。

## 一、安装 Skill 和本地依赖

如果你只是想使用，不需要先理解 Python、FFmpeg 或视频编码。先在终端安装 Skill：

```bash
npx skills add kobingogo/motion-sticker-pack -g -y -a codex
```

完整交付还需要本地媒体依赖：

```bash
python3 -m pip install -r requirements.txt
```

macOS 再安装 FFmpeg：

```bash
brew install ffmpeg
```

安装完成后，在 Codex 对话中输入：

```text
$motion-sticker-pack
```

Skill 的入口不是“直接生成九宫格视频”，而是一条有确认节点的流程：上传角色图，选择风格和 Emoji，先确认静态表情板，再生成动画、切图和打包。

## 二、四种输入方式，先选对入口

### 1. 只有一张角色参考图

这是最完整的路径。上传人物、宠物、吉祥物或其他角色图，选择风格，例如 3D、手绘、Q 版、漫画，再给出九个 Emoji 或短描述。

建议先用一组容易判断的反应：

```text
开心、喜欢、惊讶、加油、困困、谢谢、点赞、委屈、亲亲
```

静态表情板生成后，先检查角色身份、动作数量、网格布局和透明背景。确认准确后，再进入动画阶段。这个确认节点看起来多一步，但它阻止了一个常见错误：错误的静态图继续生成视频，最后才发现整套表情都要返工。

### 2. 已有静态九宫格图板

把它当作“用户提供的静态图板”，不要重新伪造一次生成审批。Skill 会先检测实际布局，再按检测结果切图。

“3×3”只是输入预期，真正处理时要以图像检测结果为准。九张图不一定真的排成三列三行，不能只看文件名猜布局。

### 3. 已有九宫格视频

先从视频抽取代表帧，确认网格布局，再进行切图。一个九宫格视频是一个动画源，不能把它误当成九个已经独立的 MP4。

项目中的处理命令形态如下，普通用户一般不需要手动执行：

```bash
python3 scripts/process_emoji_grid.py animation.mp4 works/角色名/output \\
  --layout works/角色名/layout.json --fps 6
```

### 4. 已有独立单表情 MP4

如果每个表情已经是一个独立视频，就不需要伪造一个“1×1 网格”。直接批量处理独立文件：

```bash
python3 scripts/process_independent_stickers.py stickers works/角色名/output --fps 6
```

这两条路径的差异很实际：九宫格视频需要先知道每个格子在哪里；独立 MP4 已经完成了空间拆分，只需要逐个处理和导出。

## 三、从动画到可用文件

处理完成后，重点检查四件事：

1. 每个编号对应一个独立表情，而不是整张九宫格。
2. 动画确实在变化，不能只拿第一帧当结果。
3. 透明贴纸没有被黑底或棋盘格污染。
4. 循环首尾自然，尺寸和文件大小适合目标平台。

项目的典型输出包括 Animated WebP、GIF、首帧 PNG、处理报告和 ZIP。这里有一个容易混淆的地方：GIF、WebP 和 PNG 是贴纸交付物；为了在 X 或小红书里展示整组效果，仍然应该另外保留普通 MP4。

## 四、各个平台怎么导入或上传

### 微信：适合把单张 GIF / PNG 加进个人自定义表情

微信手机端常见路径是：

1. 打开任意聊天，进入表情面板。
2. 打开“添加的单个表情”或自定义表情区域。
3. 点击加号，从相册选择一张 PNG 或 GIF。
4. 保存后，在聊天表情面板中发送。

微信这里更像“逐张收藏”，不是把一个 ZIP 直接安装成完整表情包。九宫格视频也不能直接变成九张聊天表情；先使用 Skill 切出独立文件，再逐张添加。

如果动图无法保存或播放，先尝试 GIF；如果仍然失败，缩短动画、减小尺寸和文件体积，再按当前客户端的提示重试。微信个人自定义表情和面向公众投稿的微信表情商店是两件事，后者需要另外走平台投稿流程。

### 小红书：把它当作图文或视频内容发布

小红书的重点不是导入原生聊天贴纸包，而是发布一篇图文笔记或视频笔记。小红书官方创作服务平台提供图片和视频内容的发布能力，入口可见[小红书创作服务平台](https://creator.xiaohongshu.com/publish)。

操作上可以这样做：

1. 把 `motion-sticker-pack-15s-4x5.mp4` 保存到手机。
2. 打开小红书，点击发布入口，选择视频。
3. 选择视频封面，标题直接说清“角色图 → 动态表情包”。
4. 在正文放一张输入/输出图或流程卡，再补 GitHub 链接。

小红书还可以发图文版本：第一张放 `01-input-output.png`，后面放五组案例总览、工作流卡和安装卡。4:5 适合作为当前项目的主展示比例；如果后续发现视频主体在手机预览里太小，再做一版 9:16，不要把 4:5 画面硬拉伸。

### 抖音：上传普通 MP4，不是导入原生表情包

抖音更适合把制作结果当成短视频发布。抖音开放平台的公开文档说明了视频上传接口、MP4/WEBM 等常用格式和竖版视频方向；普通创作者直接在 App 内发布即可，开发者才需要开放接口。参考[抖音开放平台上传视频文档](https://open.douyin.com/platform/resource/docs/openapi/video-management/douyin/create/upload/)。

手机端操作：

1. 点击发布入口，选择本地视频。
2. 选择 15 秒版或另行制作的 9:16 版本。
3. 封面使用黑猫或五组案例总览中的一组，不要让封面只剩命令行。
4. 文案说明“这是一个开源 Codex Skill”，评论区再放仓库地址。

当前 4:5 视频可以用于 X 和小红书。抖音若是主要发布渠道，建议单独制作 9:16 版本；这是展示画幅的适配，不代表表情包本身必须是竖屏。

### X：使用 MP4 做结果展示

X 的推广目标是让读者在几秒内看懂结果，所以首发使用：

- 15 秒 4:5 视频：主帖
- 42 秒完整视频：回复或 Thread
- 6 秒黑猫循环：技术细节或案例回复
- 流程卡、安装卡：补充说明

主帖只讲一个动作：从 GitHub 安装 Skill。不要在同一条内容里同时要求读者点赞、转发、评论和提交 Issue。

### WhatsApp：按贴纸包规格准备单张文件

WhatsApp 官方帮助中心目前提供了从贴纸面板创建自定义贴纸、把选中的贴纸加入新贴纸包的路径；最新 Android 和 iOS 客户端的入口可能不同，缺少入口时先更新应用。参考[WhatsApp 官方自定义贴纸说明](https://faq.whatsapp.com/1056840314992666/)。

常见操作：

1. 打开聊天，进入贴纸面板。
2. 选择 Create / 创建，或使用编辑贴纸入口。
3. 从手机相册选择单张 PNG、WebP 或可用的动画文件。
4. 选择“添加到贴纸包”，新建或加入现有贴纸包。
5. 在聊天中发送，或使用分享贴纸包入口分享给联系人。

官方说明中的关键约束包括：静态贴纸使用 PNG 或 WebP，单张静态图最大 100KB、500×500 像素；贴纸包包含 3–30 张。动画贴纸有单张 500KB、512×512 等限制，并且同一动画包需要保持动画格式一致。具体限制以当前帮助中心和客户端校验为准。

因此，不能把当前 1080×1350 的 X 宣传片，也不能把一个包含几十个文件的 ZIP，直接当成 WhatsApp 贴纸包。正确做法是使用 Skill 输出的单张贴纸，再生成 WhatsApp 专用尺寸和体积版本。

### Telegram：静态贴纸和 Video Sticker 是两条路线

Telegram 官方文档把静态贴纸、TGS 动画贴纸和 Video Sticker 分开定义。普通用户可以在聊天中的贴纸面板点击加号使用内置编辑器，也可以通过 `@Stickers` 创建和管理贴纸包。完整说明见[Telegram Stickers 官方文档](https://core.telegram.org/stickers)。

#### 静态路线

使用单张 PNG 或 WebP，通过贴纸编辑器或 `@Stickers` 加入贴纸包。透明 PNG/WebP 更适合从本项目的单张输出继续处理。

#### 视频贴纸路线

如果要把动态结果作为 Telegram Video Sticker 上传，需要导出专用 WebM，而不是直接上传 MP4。官方要求包括：VP9 编码、无音频、最长 3 秒、最高 30 FPS、贴纸一边为 512 像素、文件不超过 256KB，并建议循环播放。

这意味着项目里的 6 秒展示片段不能直接作为 Telegram Video Sticker。应从独立表情源重新截取不超过 3 秒的片段，再导出 VP9 WebM；如果要保留透明，还要确认编码过程没有把 Alpha 拍成黑底。

## 五、遇到失败时，先判断是哪一层出了问题

### 预览里看起来是静态的

如果看到的是开场“输出预览”，那部分本来就是用 Emoji 画出的静态说明卡，用来解释输入和输出关系。真正的动画在后面的案例展示区域。

判断动画是否存在，不要只看封面。拖动视频时间线，或者比较同一角色前后两个时间点的帧；如果两帧完全相同，才需要继续排查。

### 九宫格外面有黑底或紫色边

这是展示视频的背景和卡片区域没有统一，不等于源贴纸没有透明通道。X 宣传片可以统一使用深色实底；聊天贴纸则要回到单张 PNG/WebP/透明 WebM，不要从已经拍扁的 MP4 反推透明。

### 九宫格视频和独立 MP4 不知道选哪个

只有一个带九宫格的动画文件，就走网格检测和切图；每个表情已经各自有 MP4，就走独立文件批处理。不要为了让文件看起来统一，给独立表情伪造 1×1 布局。

### 九宫格有空格

如果原始案例确实少一个结果，空格就应该保持为空。比如宝宝案例的第六格是留空，不应再叠加“源素材为空”的占位卡。占位文字会让宣传图看起来像程序报错，也会污染最终表情包布局。

## 结语：先做一个源包，再做平台派生包

最省事的组织方式是保留一个“源包”和若干“平台派生包”：

```text
源包：单张 PNG / GIF / WebP + 动画 WebM + ZIP
  ├─ X / 小红书：4:5 MP4
  ├─ 抖音：9:16 MP4
  ├─ 微信：逐张 PNG / GIF
  ├─ WhatsApp：符合客户端限制的 PNG / WebP / 动画包
  └─ Telegram：PNG / WebP，或 ≤3 秒 VP9 WebM
```

已经验证的部分是：`motion-sticker-pack` 可以从角色图、静态图板、九宫格视频或独立 MP4 进入处理，并输出独立贴纸文件和 ZIP。合理推断是：同一个源包经过尺寸、时长和编码转换，可以覆盖更多聊天平台；尚待验证的是每个平台客户端在不同手机系统、地区和版本下的具体入口与临界文件限制。

如果你是第一次操作，推荐顺序只有四步：先用 Skill 生成并检查一套表情；再用 MP4 发小红书、抖音或 X；然后把单张文件加入微信；最后针对 WhatsApp 和 Telegram 各导出一份专用规格。这样每一次失败都能定位到“制作、编码还是平台导入”，而不是重新猜一遍整个流程。
